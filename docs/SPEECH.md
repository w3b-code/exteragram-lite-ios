# Local audio transcription

The port adds **Transcribe on this iPhone** to the context menu of downloaded voice messages, round videos and audio files. The action converts voice/Opus media to AAC with Telegram's existing converter, requests Speech authorization, then uses Apple's on-device recognizer. The result is stored with Telegram's existing local-transcription API and shown in an alert with a Copy action. The loading indicator supports cancellation. Ephemeral, secret-media and copy-protected messages do not expose the action.

No remote audio URL is accepted by the transcription API. Production recognition requires both a recognizer reporting `supportsOnDeviceRecognition` and a request with `requiresOnDeviceRecognition = true`; the adapter never forces the capability flag. Missing models, denied permission, unsupported languages, invalid audio, no detected speech, cancellation and timeout have explicit outcomes. Apple documents the [on-device requirement](https://developer.apple.com/documentation/speech/sfspeechrecognitionrequest/requiresondevicerecognition) and [capability check](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition).

The Info.plist patches supply `NSSpeechRecognitionUsageDescription`. The adapter checks that it is nonempty before requesting permission because Apple's [authorization API](https://developer.apple.com/documentation/speech/sfspeechrecognizer/requestauthorization(_:)) requires this key. This feature transcribes files and does not request microphone access. Telegram's normal media download is separate: the menu action requires a completed download and does not start its own fetch.

## Public Swift API

`ExteraSpeechTranscriber.transcribe(fileURL:localeIdentifier:partial:completion:)` returns an `ExteraSpeechTask` whose `cancel()` is idempotent. Completion occurs once, and accepted partial results precede completion on a serial delivery queue targeting the supplied callback queue (main by default). The timeout defaults to 120 seconds, including time awaiting authorization. Cancellation during a pending authorization prevents its eventual callback from starting recognition. If cancellation races an already starting backend task, the returned backend task is canceled immediately.

`ExteraSpeechTranscript` contains `text` and `isFinal`. `ExteraSpeechError` distinguishes authorization, unavailable on-device recognition, locale, file, cancellation, timeout and recognizer failures. `ExteraSpeechLocale.resolve` selects an exact supported locale; a language-only request may choose its preferred regional variant. An explicit unsupported region is not silently replaced.

`ExteraSpeechBackend` is injectable for tests. `AppleOnDeviceSpeechBackend` is the production iOS implementation; other platforms return `unsupportedPlatform`. The package targets iOS 15 or later. The Bazel module uses the same two source files as SwiftPM, with Foundation, Speech and AVFoundation imported by the implementation; it has no third-party package or service dependency.

## APK evidence and adaptation limits

The supplied APK is `exteraGram-lite-universal-20261004.apk`, SHA-256 `adbead84d31057fbe2d58433fe4f51f09463eb0c007d82ae28df2344462777ed`. Focused JADX inspection of `com.exteragram.messenger.speech.VoiceRecognitionController`, `speech.recognizers.VoskRecognizer` and `speech.utils.FormatConverter` showed a registered `vosk` recognizer, local model loading, audio conversion to PCM and a recognizer using the source sample rate. The APK's recognition information describes offline Vosk recognition. The controller also supports optional AI text postprocessing. No developer API keys were extracted or reused for this implementation.

This adapter implements the local-transcription function with Apple's installed models. It does not reproduce Vosk's model files, model downloads, accuracy, supported-language set, provider/model identifiers or optional AI postprocessing. The UI uses the app's current language, so multilingual recordings can require switching the app language. It offers no model downloader or per-message language picker. If Apple's recognizer cannot provide on-device recognition, the action fails without a network fallback. A device reporting support can still fail at runtime when a model or service is unavailable.

The menu handles one selected message and already downloaded media. It does not automatically download audio or transcribe live microphone input. The preparation stage has a separate 120-second timeout; recognition has the API's 120-second timeout. Long recordings can therefore time out. Temporary converted audio is removed on completion/cancellation. Telegram's existing server transcription and its eligibility checks remain independent.

## Validation status

Eight deterministic Swift tests cover locale selection, partial/final ordering and exactly-once completion, unavailable offline models, denied permission, cancellation while authorization is pending, timeout cancellation, rejection of remote URLs, and empty-file versus empty-transcript failures. These tests use an injected backend and intentionally do not prompt for Speech permission or measure recognition accuracy. The macOS test build uses the non-iOS platform stub; CI must additionally typecheck the iOS implementation against the iPhoneOS SDK.

An aggregate `python scripts/apply_port.py ../upstream --check` passed against pinned Telegram-iOS commit `f1dd7a2dbd02cbbf513e75d5695d8d36d1cf5838` after the speech patches were first added. After the copy-protection guard was added, all four final speech anchors were independently checked against `git show HEAD:<path>` and matched exactly once. An aggregate rerun then encountered an unrelated missing sparse-checkout file, `submodules/TranslateUI/Sources/TranslateScreen.swift`; it needs to be repeated after that source is present. The new Swift tests, iOS typecheck, full Telegram application compilation, permission dialogs, actual AAC/Opus/round-video transcription and Feather-signed device behavior still require CI/device verification. Static checks alone do not establish complete feature parity with the APK.
