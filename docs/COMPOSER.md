# Composer preferences

The supplied Lite's `getDisableMarkdown` has three statically identified consumers: `MediaDataController.getEntities`, `EditTextBoldCursor.addMarkdownToggle`, and `EditTextBoldCursor.onTextContextMenuItem`. The editor menu exposes Enable/Disable Markdown. This is not a request to remove explicit formatting entities.

The iOS patch gates the common `TextFormat.convertMarkdownToAttributes` transformer. When disabled, it returns the original attributed string, retaining visible delimiters, manual formatting and mention entities. When enabled, the native parser runs unchanged. This shared transformer is used by normal send/edit and related rich-input paths. A real switch is exposed in exteraGram settings; the Android-style quick editor-menu toggle remains to be added. `addCommaAfterMention` is connected to the chat autocomplete panel and MessageInputPanelComponent. Both username and name-entity paths append comma-space for non-bot users/channels, and plain space for bots or when disabled. The suffix stays outside the name entity and native replacement helpers preserve UTF-16 selection offsets. Static `ChatActivity.lambda$createView$51` confirms this bot exception. Other Android gesture/append-mention paths remain to be matched against native equivalents.

This source integration is not a device behavior claim. See VALIDATION.md for actual compilation results.
