# Native feed transport primitives

Status: source integration awaiting native compilation. This is not a live feed, a complete coordinator or device/network validation. The portable core and UI remain separate layers.

`exteraFeedLoadDialogPage` reads one root/archive page (folder 0 or 1), fetching pinned dialogs on the first page and excluding them from raw pagination. It returns eligible joined broadcast channels with native peer metadata and read counters. Communities/groups/left channels are filtered after raw page progress is determined. Follow the returned cursor across every page of both folders; an empty filtered result is not exhaustion. The opaque cursor binds the account peer, folder, real message index and retained input peer/access hash, so it does not require writing peers to Postbox before the next request. Missing top-message dates/access hashes or a non-advancing page are explicit errors. A result is not an atomic snapshot of channel membership across concurrent changes.

`exteraFeedLoadHistoryPage` reads older pages of full native `Message` objects and media references, retaining genuine peer/namespace/message IDs and timestamps. Raw IDs advance past empty server records; those unavailable IDs are separate because they have no trustworthy date. The caller must not invent a date or declare a chronological coverage boundary from them. A first-page upper bound can be retained for later pages, new messages are excluded by that explicit snapshot bound, and exhaustion requires an actually successful empty history response. Service records remain available for filtering in the coordinator. Associated reply hydration is not added.

Both functions use authenticated native Telegram RPCs and only read Postbox metadata for merging. They do not insert history/peers, mark read, increment views, forward/delete messages, download media binaries, or run retries. Disposal propagates cancellation; a 30-second timeout and typed RPC/invalid-response/cursor errors preserve incomplete states. No user account requests were executed during development.

Pending: a complete catalog-driving loop and membership watchers, newer-history and cache/hole adapters, mapping unavailable raw records into conservative feed coverage, cancellation/session/config scheduling and cache limits, native feed UI/entry order/read visibility and actions. Existing native `MessageIndex` tie ordering differs from Android; exact feed ordering must be handled at the UI entry/comparator level while preserving real IDs. Twenty-seven exhaustive custom-kind switches, two business helper switches and multiple hashtag-specific branches need review for a new feed kind. No tab is exposed by these primitives.

Signatures and field mappings were checked against pinned Telegram iOS `f1dd7a2dbd02cbbf513e75d5695d8d36d1cf5838`, including `FetchChatList.swift`, `ApiUtils.swift`, `MessageUtils.swift`, `ChatController.swift`, `ChatHistoryListNode.swift` and the previously integrated export RPC adapter. Native compilation, account-level pagination and device behavior remain unverified.
