# Translation reconstructed from the selected Lite APK

The native selected-message translation entry point in `TranslateUI.presentTranslateScreen` reads `ExteraSettings.translationProvider`. The ordinals match APK `TranslationProviders.ALL`: 0 Telegram, 1 Google, 2 Yandex, 3 Microsoft. An invalid value falls back to Google, as in the APK. The settings screen exposes Telegram, Google and Yandex. Selecting an external provider and invoking Translate sends that selected text to that provider.

The UIKit translation sheet displays the result, supports cancellation, retry, choosing a target language, copying when the original action permits copying, and replacing text when the caller supplies that callback. It respects an explicit caller target before the persisted `targetLang`; `app` resolves to the current Telegram interface language. Chinese script identifiers are adapted to the provider. Changing the target in the sheet persists it. Plain-text translations return an empty entity array when replacing; original entity offsets would be invalid after translation.

## Evidence and scope

Input: `exteraGram-lite-universal-20261004.apk`, SHA-256 `adbead84d31057fbe2d58433fe4f51f09463eb0c007d82ae28df2344462777ed`, static decompilation of `com.exteragram.messenger.translator`, including `TranslationProviders`, `GoogleTranslator`, `YandexTranslator`, `MicrosoftTranslator`, `TranslationModels` and `HttpResponseUtils`. The source is reconstructed native Swift, not copied Java or an Android runtime wrapper.

Google and Yandex below are the application's recovered network contracts. They are **not guaranteed public or supported APIs**. The reconstruction has not sent user messages to either service for validation. A service can reject these requests, change its protocol, require credentials or stop responding. Such failures are shown in the sheet; text is never silently sent to another provider. The iOS client identifies itself as `exteraGram-Lite-iOS/1`, rather than impersonating the Android app.

Server-translated entities are preserved for replacement. No third-party HTTP request or alternative-provider fallback is made. |
| Microsoft | Official Azure Translator v3 POST JSON `[{"Text":"..."}]`, `api-version=3.0`, `to`, optional `from`, user's `Ocp-Apim-Subscription-Key` and optional region. | Core supports user-configured Azure credentials. It is not offered as a selectable ready provider because a credential configuration UI is not implemented. |

The APK's Microsoft adapter uses an Android-app signature credential. That credential is not copied, extracted into configuration, committed or reused. The optional native adapter instead follows [Azure's documented translation API](https://learn.microsoft.com/en-us/azure/ai-services/translator/text-translation/reference/v3/translate) with the user's own resource. A missing key throws `configurationRequired` before a request. If an existing preference is 3, the sheet reports this configuration error.

## Limits, errors and text handling

- Google: at most 20 text parts, 5,000 UTF-16 units per part, 8,000 units per request. Yandex: 20 parts, 5,000 units per part and request. Microsoft conservatively uses the same 5,000-unit request cap.
- Long text splits at grapheme boundaries, preferring whitespace boundaries. Newline sequences and each part's surrounding whitespace stay local and are reassembled exactly. A grapheme larger than the provider limit is rejected. No substring offsets or message entities are guessed.
- Requests are sequential, below the APK's two-concurrent-request cap. There are at most four attempts with cancellable exponential backoff. Numeric `Retry-After` values up to 30 seconds are respected; longer server cooldowns return a rate-limit error for a later explicit retry, rather than retrying too early. No message text is logged or cached by this module.
- HTTP 429 and Yandex 1052 are rate limits; Yandex 501 means unsupported language. HTTP 5xx, transport failures and malformed successful responses may retry. Other HTTP errors are rejected. Array length must match the request; partial responses are never returned as complete translations.
- Default networking is ephemeral, with cookies, credentials and URL cache disabled. Redirects are restricted to HTTPS on the original host. An injected URLSession is caller-owned, including its own redirect policy.
- Total input is capped at one million UTF-16 units and response validation rejects bodies over two million bytes. The latter is a post-download validation cap, not a streaming transport limit.

## Integration and remaining work

`ios/ExteraTranslation` is a Foundation-only Swift package, with conditional FoundationNetworking for portable mock tests. `port/patches/translation.json` adds the selected-message dispatch and direct `TranslateUI` dependencies on `ExteraPreferences` and `ExteraTranslation`. The overlay adds the UIKit sheet in `TranslateUI`. The central port application script must copy the package's Swift sources into `submodules/ExteraTranslation/Sources` and generate the public `ExteraTranslation` Bazel swift_library. No additional external library or service key is required for the Google/Yandex adapters.

Upstream is pinned to `f1dd7a2dbd02cbbf513e75d5695d8d36d1cf5838`. Its `presentTranslateScreen` uses the Apple system presentation on supported iOS 18 configurations and has an empty non-system branch. This patch replaces that dispatch with the new sheet for all selected providers, including a real Telegram engine subscription for provider 0. The sheet does not depend on that system branch and works from iOS 15. Telegram errors such as flood limits, unsupported languages, text limits and a server request to use an alternative are shown; the selected provider is never changed automatically. Continuous whole-chat translation and automatic message translation are **not wired** by this patch. External services return plain text, while Telegram's translated entities are preserved for replacement. The sheet currently supplies common target languages rather than the APK's complete language catalog. UI labels have English/Russian variants; other interface languages use English. Microsoft credential entry/storage, full language localization, device UI verification and live endpoint verification remain outstanding.

Tests use URLProtocol mocks only: request encoding and response formats, provider batch limits, Unicode segmentation, exact whitespace/newline reassembly, missing Microsoft configuration, official Microsoft subscription headers, malformed response counts, rate limits, forbidden HTML responses, Yandex error codes, empty input, invalid languages and cancellation before dispatch. These tests do not prove live service availability or a complete IPA build.

A separate live protocol smoke check on 2026-10-20 sent the fixed, non-user test phrase `Good morning.` from English to Russian with the native iOS user agent. Google returned HTTP 200 with a string array; Yandex returned HTTP 200 with `code: 200` and a `text` array. No account credentials or user conversation were sent. This establishes that those exact contracts responded from this network at that time; it does not test the Swift transport on an iPhone or guarantee future availability.
