# IPA без подписи и установка через Feather

GitHub собирает device IPA, а подпись выполняется на iPhone. Сертификат и профиль не загружаются в этот репозиторий. Возможности установленного приложения определяет профиль, который Feather применит при подписи; сам IPA не может добавить отсутствующие entitlements.

## Хранилище основного приложения

Официальный Telegram iOS использует `group.<bundle identifier>` для общей базы приложения и расширений. В исходной точке запуска отсутствие контейнера завершает инициализацию экраном `Error 2`. `port/patches/sideload.json` заменяет только выбор контейнера основного приложения:

1. Если контейнер App Group доступен, используется исходный общий путь.
2. Если он недоступен, основной клиент создаёт постоянный каталог `Library/Application Support/ExteraSideload/telegram-data` внутри собственного sandbox.
3. Если и этот каталог создать нельзя, возвращается исходный экран ошибки хранилища. Временное хранилище и новый случайный путь на каждом запуске не используются.

Исходная процедура генерации и сохранения `.tempkey`, соль базы данных и шифрование остаются без изменений. Патч не копирует, не удаляет и не заменяет существующие базы. Он не пытается обойти изоляцию контейнеров iOS.

При обновлениях нужно сохранять bundle identifier и одинаковый набор entitlements. Если после обновления App Group станет доступен или исчезнет, выбранное хранилище изменится: прежние файлы не удаляются, но аккаунты из другого контейнера не появятся автоматически. Перенос уже используемой базы между контейнерами не реализован. Удаление приложения средствами iOS удаляет его sandbox.

## Keychain и подпись другой командой

`BuildConfig.keychainAccessGroupForBaseAppBundleId` уже получает seed действующей подписи через Keychain во время выполнения. Патч не подменяет его значением `0000000000` и не фиксирует команду сертификата в исходниках.

В обычной конфигурации сохраняется исходная логика PasscodeCore с App Group и частной biometric-группой. Только когда основной процесс не имеет доступного App Group, запросы PasscodeCore не задают `kSecAttrAccessGroup` явно. iOS использует частную группу текущего приложения, которую разрешает фактическая подпись. Доступность, ACL, биометрические условия и содержимое passcode-записей остаются прежними. Расширения не получают такого fallback и не создают отдельные несвязанные passcode-ключи.

Если после переустановки изменится разрешённая Keychain-группа, старые защищённые элементы могут стать недоступны. Этот патч не отключает passcode-защиту и не обещает перенос Keychain между разными подписями.

## Расширения без App Groups

Каждое расширение имеет отдельный sandbox. Создание в нём собственной базы вместо общей привело бы к независимым аккаунтам и несовпадающим ключам, поэтому fallback основного приложения в расширения не добавляется.

- Share Extension отменяет запрос с понятной ошибкой вместо пустого незавершающегося экрана.
- Notification Service сразу возвращает исходное содержимое push, если общий контейнер недоступен, вместо ожидания истечения времени расширения. Это не включает доставку APNs при отсутствующем push-entitlement.
- Исходный WidgetKit guard уже выдаёт завершённый fallback timeline без общей базы; он сохранён.
- Исходный Broadcast Upload guard уже вызывает `finishBroadcastWithError`, если контейнер недоступен; он сохранён.
- Notification Content и Siri продолжают использовать только реальный общий контейнер. Этот патч не делает их функциональными при отсутствии разрешённого App Group.
- Для фонового URLSession `sharedContainerIdentifier` задаётся только при доступном общем контейнере.

Без соответствующих entitlements не гарантируются APNs, общие виджеты/Share, iCloud, Siri и общая работа расширений. Фоновые ограничения iOS также сохраняются.

## Проверка

Пять replacement-anchors проверены на закреплённой ревизии upstream `f1dd7a2dbd02cbbf513e75d5695d8d36d1cf5838`; исходный checkout при подготовке патча не изменялся. Overlay `ExteraSideloadStorage.swift` включается существующим glob `TelegramUI/Sources/**/*.swift`. `apply_port.py` должен проверять все anchors до записи и завершать работу при несовпадении версии.

Пока это статическая проверка: запуск подписанной сборки на iPhone ещё не выполнен. Проверка после получения IPA:

1. Подписать и установить с фиксированным bundle identifier без App Groups. Убедиться, что клиент открывается без `Error 2`.
2. Войти в тестовый аккаунт, перезапустить приложение и проверить сохранение сессии и passcode. Повторить после обновления IPA без удаления приложения.
3. Проверить установку passcode и биометрию при доступном Face ID/Touch ID; отсутствие доступа к Keychain должно давать ошибку, а не отключать защиту.
4. Вызвать Share: если App Group отсутствует, расширение должно завершиться с ошибкой, не зависая и не создавая отдельную базу.
5. При профиле с разрешённым App Group проверить, что используется исходный общий контейнер и расширения разделяют аккаунты с основным приложением.
