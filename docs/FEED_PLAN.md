# Lite feed: evidence and implementation plan

Status: analysis and plan only. This pass does not implement or enable an iOS feed, change application code, execute the APK, or establish runtime feature parity.

The supplied Lite contains a substantial custom feed implementation. The pinned iOS tree has reusable chat rendering, history and read-state infrastructure, but **does not contain a working aggregate-feed backend**: `TelegramCore/Sources/TelegramEngine/Messages/FeedHistory.swift` is exactly one LF byte. A native feed requires a new backend and UI adapter, rather than exposing that file through a new tab.

## Evidence boundary

Artifact: `exteraGram-lite-universal-20261004.apk`, version 12.10.6 Lite, SHA-256 `adbead84d31057fbe2d58433fe4f51f09463eb0c007d82ae28df2344462777ed`. Existing APK member inventory and preference recovery were reused. Focused static decompilation used the installed `jadx-headless-mcp-0.7.1-all.jar`, SHA-256 `6e5eacf500b64292bfb73c49797c1958f6ee44646e43e868039ae7feb573ff75`, with the existing Java 21 runtime. No developer credentials were inspected or reused.

Fifteen initial classes were selected under `com.exteragram.messenger.feed` and its `ui`/`ads` packages: config, registry, controller, loader, store, identity map, backfill, unread tracker, message utilities, channel actions, two UI classes and three ad classes. A second focused selection added `FeedChatIntegration` and `FeedRequestNormalizer`. These are static reconstructions, not observed Android behavior. The first run reported 21 transitive JADX errors; the second reported four, in dependent `MessagesController`/`MediaDataController` methods. `FeedChannelsActivity.onClick` also contains an embedded JADX diagnostic. Do not treat every decompiled expression or dependency as verified source. Exact low/medium-device cache constants and the complete semantic mapping of Android numeric menu IDs remain unresolved.

Native comparison is against `TelegramMessenger/Telegram-iOS` commit `f1dd7a2dbd02cbbf513e75d5695d8d36d1cf5838`. Read-only `git show`, `git grep` and `git cat-file -s` were used, so working-tree patches did not alter the comparison. The finding labels below are local analysis labels, not retained REA-server evidence IDs.

## Recovered Lite contracts

| Finding | Observed contract | Static source |
| --- | --- | --- |
| F1: channel scope | Eligible channels satisfy `isChannelAndNotMegaGroup`, are not communities, and are not left/kicked. This is a feed of joined broadcast channels; it is not a public-post search or combined groups/inbox feed. | `FeedController.isEligibleChannel`; `FeedChannelRegistry.rebuild` |
| F2: configuration | `feedconfig<accountIndex>` holds `includeArchived` (default false) and `excludedChannels` (set of signed dialog IDs, default empty). A generation counter changes when these values change; immutable snapshots accompany enumeration. | `FeedConfig` constructor, setters, `snapshot` |
| F3: global presentation | `showFeedTab=false`, `showFeedUnreadCounter=true`, `widePostsInFeed=true`. These already exist as definitions in the port's preference package; their presence alone does not implement a feed. | Existing preference provenance; `FeedChannelsActivity.fillItems` |
| F4: enumeration | The loader enumerates local dialog/channel metadata, checks eligibility, excludes archive folder 1 unless enabled, then removes excluded channels from included rows. Channel existence and included-channel count are distinct states. Membership changes rebuild the registry. | `FeedTimelineLoader.buildChannelSet`; `FeedChannelRegistry.rebuild` |
| F5: timeline | Cached `messages_v2` rows across included dialog IDs are queried using `mid > 0`. Empty messages and service-action messages are filtered. The stable cursor is `(date, signed dialog ID, real message ID)`, not message ID alone. Older queries use descending tuple order; the store compares that tuple consistently. | `FeedTimelineLoader.loadChunk`, `compareDesc`, `readMessage`; `FeedStore.compareTimeline` |
| F6: paging and albums | Older chunks contain 30 raw rows; newer pages contain up to 50. Initial loading considers an unread boundary. Trailing albums receive additional cached members and grouped messages are clustered before presentation. Raw-row progress must survive filtered-out messages. | `FeedTimelineLoader.loadOlderPage`, `loadNewerPage`, `completeTrailingAlbum`, `clusterGroupedMessages` |
| F7: backfill | Missing local depth/holes produce per-channel backfill candidates. A round starts at most four channel loads, requesting 20 messages per channel, with a ten-second round timeout. Requests carry account/session/load identities; cancellation and exhaustion are tracked. | `FeedBackfillCoordinator.startRound`, `cancel`, result/failure handlers; loader depth/hole queries |
| F8: identity | Android allocates decreasing synthetic row IDs and retains a mapping from `(real dialog ID, real message ID)`. Outgoing request fields are normalized back to real IDs; this also covers nested invoice/message-ID cases. Synthetic feed IDs must never become Telegram API IDs. | `FeedMessageIdentityMap.register`/resolvers; `FeedRequestNormalizer.normalize` and metadata normalization |
| F9: unread count | The total badge is the sum of unread counts from all eligible, included dialogs subject to archive policy. It is not merely the number of unread rows in memory. No muted-channel exclusion appears in the inspected unread filter. | `FeedUnreadTracker.collectUnreadFeedDialogs`, `getUnreadCount` |
| F10: seen/read effects | Seen posts accumulate a maximum real message ID per original channel, then flush after about one second through normal dialog-read APIs. Sponsored posts are excluded. Actual visibility is gated by active viewport, unpaused host, completed initial positioning, read readiness, no pending divider/restore, and no sheets. Loading/prefetch alone is not a read event. | `FeedUnreadTracker.onPostSeen`, `flush`, `isUnread`; `FeedChatIntegration.canMarkVisibleAsRead`, `onPostCellVisible` |
| F11: mark all read | A confirmed action marks eligible included dialogs read up to their known top message, also marks mentions read, and reconciles pending read maxima. Hidden/archived-excluded channels are outside its scope. | `FeedActivity.showMarkAllReadDialog`; `FeedUnreadTracker.markAllRead` |
| F12: updates/lifecycle | Edits, deletion, channel-set/config changes, new posts, reply/view counters and read-state changes reconcile with the store. Config/session generations reject stale results. Active/resumed clients are counted; last active-client release cancels loads and trims cache. Scroll position and initial unread positioning are preserved. | `FeedController`; `FeedStore`; `FeedChatIntegration` |
| F13: channel actions | Settings have channel search, title ordering, shown/hidden groups, include/exclude all, archive and presentation switches. Avatar actions open the original channel, hide it with Undo, or leave through the existing confirmation. Creator channels do not expose Leave. | `FeedChannelsActivity`; `FeedChannelActions`; `FeedChatIntegration.hideChannelWithUndo`/`undoHideChannel` |
| F14: interaction filtering | Feed context actions use an explicit numeric allowlist. Double-tap allows action IDs 1,2,3,4,6,9; swipe additionally excludes 1. Post merging requires the same channel/content type/direction, no preceding inline keyboard, a five-minute date window, compatible guest-chat origin and no paid-message condition on the checked following post. | `FeedMessageUtils.isAllowedFeedOption`, gesture guards, `shouldMergePosts` |
| F15: sponsored rows | A separate feed ad catalog is loaded through Telegram channel history, parsed into manifests/body/media, filtered by app locale and premium/badge matching, and rotated with weights. Configuration controls enablement and spacing. Defaults observed include first-after/every 30, trailing minimum 2; small eligible pools increase spacing. Success is cached for 30 minutes and failure for one minute. Anchors respect album boundaries and stable positions. | `FeedAdController`, `FeedAdParser`, `FeedAdInjector` |

F7's error handler can mark a failed source exhausted in the reconstructed Android implementation. For iOS, permanent end-of-history and temporary network/flood errors should be separate states, with explicit retry. Otherwise a transient failure can silently remove content. This is a deliberate reliability adaptation, not exact failure-behavior parity.

The inspected feed classes use the account's existing Telegram channel access and ordinary history/read/action requests. No separate feed-specific server API or premium requirement for viewing the timeline was identified in this bounded inspection. This does not establish the absence of every gate elsewhere in the app. Premium and badge conditions are positively observed for the separate ad catalog.

A bounded search across pinned TelegramUI, AccountContext and TelegramEngine found no `FeedHistoryContext`, `feedHistory` implementation or feed-specific controller. `MediaManager.swift` has a legacy audio-playlist `feed(Int32)` case, but no `.feed(...)` construction was found in TelegramUI/AccountContext; this is not evidence of a usable post-feed screen.

Native `MessageId` already includes peer and namespace. Keep it unchanged throughout the feed, gallery, audio playback, reactions, replies, links, selection and requests. Porting Android's synthetic-ID/reflection normalizer would add avoidable correctness risk. For parity in equal-date ordering, use an explicit comparator compatible with Android's negative channel dialog ID; do not assume native `PeerId.toInt64()` ordering is identical.

## Concrete full-implementation sequence

1. **Define and test a feed core.** Add `ios/ExteraFeed` for value types, account/config generations, channel inclusion, full composite identities, tuple cursor ordering, merge/dedup/edit/delete reconciliation, album grouping, unread boundaries and scroll anchors. Keep real Telegram objects in an adapter, outside this portable core. Test equal timestamps and identical numeric message IDs across different channels. Resolve remaining numeric-action semantics against Android call sites before declaring gesture/menu parity.

2. **Persist account-local selection.** Add account-scoped include-archive/exclusion data using a stable account record identity; Android's transient 0–15 account indexes should not become permanent iOS keys. Keep the three existing global display preferences at their current defaults. Invalidate the channel generation on inclusion/archive changes. Model no joined channels, all excluded, empty loaded cache, loading, recoverable failure and true exhaustion separately. Search and bulk selection must act on the whole eligible channel set, not only the visible search results unless that policy is explicitly presented.

3. **Implement `ExteraFeedContext` in TelegramCore.** Enumerate all joined broadcast channels across main/archive chat-list pages, following list holes/pagination instead of a fixed tail count. Reuse normal peer membership and channel type checks; private joined channels are allowed when the account can read them. Observe cached per-channel histories and membership/read changes, combine them with a k-way merge, and retain explicit per-source older/newer cursors and coverage. Do not query Android `messages_v2` or transplant its SQL into Postbox. Avoid publishing a claimed complete chronological page until every included source covers its horizon, or expose that partial/loading state explicitly.

4. **Add cancellable hole filling and lifecycle.** Reuse the native per-channel history/hole-fetch machinery where it preserves full media/messages, starting from bounded concurrency comparable to Lite's four sources per round. Round cancellation, timeout, temporary RPC errors, flood wait, inaccessible/left channels and genuine empty history must remain distinct. Apply account/session/config-generation checks to every result. Backfill enough to reach the initial unread boundary, complete edge albums, support newer refresh and preserve the viewport while inserting. Release fetches on loss of the last visible UI client; add bounded inactive retention based on measured iOS memory use. Android's low/medium symbolic cache constants remain unresolved and must not be copied as guessed values.

5. **Create an actual feed screen using native message rendering.** Add `ExteraFeedController` and a history adapter that reuses `ChatHistoryListNode`/bubble items with a full custom history view. Give the source explicit feed older/newer-load and visible-message hooks; an explicit feed source/kind extension is preferable to abusing the hashtag-search kind. Audit all affected exhaustive switches. Hide peer-composition/input behaviors that have no single source channel. Implement original-channel headers/avatar navigation, unread divider, new-post/pagedown count, scroll restore, empty/error/retry states, album layout, wide-post mode, iPad layout and theme changes. Connect an optional bottom tab and another stable navigation entry; do not expose a preference that only opens an empty controller.

6. **Wire unread and post actions to original peers.** Read receipt candidates must come from genuinely visible post cells after initial scrolling settles, while the scene/feed viewport is active and unobstructed. Batch per-peer maxima and apply native read APIs; exclude ads. The badge must use all included channels' server/local read counters. “Mark all read” needs its explicit confirmation and source scope, including mentions as supported by native APIs. Forward, copy, translate, transcribe, save/share, reactions, comments, links and gallery/audio playback must receive the real post and peer; native permissions and content protection apply independently for each source. Port the verified gesture/action allowlist semantically. Hide-with-Undo is local selection, distinct from leaving a channel; Leave uses native role checks and confirmation.

7. **Finish settings and sponsored-row parity.** Implement shown/hidden/search/bulk channel settings and react immediately to membership/archive changes. The supplied Lite also contains sponsored feed rows, so full parity must include a deliberate implementation or explicitly record this remaining difference. A parser/eligibility/rotation/spacing core can be implemented and tested without contacting any service. The catalog provider, remote-config contract and extera badge capability require a separately verified integration; unavailable badge/service data must not be faked. Keep official Telegram sponsored-message behavior independent. Do not mark proprietary catalog behavior complete merely because placeholder ad cards render.

8. **Prove the end-to-end behavior before enabling the tab.** First run portable-core tests, adapter tests with interleaved cache/network/update events, full pinned iOS compilation and patch reapplication checks. Then use an authorized test account/device for channel counts above one chat-list page, main/archive and muted channels, no channels/all excluded, private joined/inaccessible channels, simultaneous membership/config/account switches, offline/timeout/flood retry, edits/deletes, split albums, identical IDs across peers, scrolling both directions, paused/covered views, unread badge/divider and mark-all scope, Undo/Leave, comments/reactions/forwarding, content protection, media playback, process restoration and memory pressure. Verify visual wide/narrow modes and sponsored-row boundaries. Log only IDs/state needed for diagnosis, not user message bodies or credentials.

## Completion criteria and remaining unknowns

The work is complete only when the new tab presents a live, correctly scoped timeline from every included eligible channel, both directions page without loss/duplicates, original post identity survives every action, and read effects match actual visibility and explicit mark-all scope. The three display preferences must alter the working screen. Definitions, a channel list, a static combined cache sample, or opening the first channel do not satisfy that criterion.

Before implementing exact behavioral parity, resolve: Android context-menu numeric IDs at their action dispatch sites; low/medium inactive cache constants from bytecode or runtime evidence; the exact UI visibility booleans passed to `onPostCellVisible`; proprietary badge/remote-config catalog behavior; and remaining decompiler-sensitive expressions in initial unread loading/settings callbacks. Actual Android/iOS runtime comparison and all device acceptance checks remain unperformed. Ordinary Telegram access supplies a viable native backend foundation, but it does not remove this work or establish full parity.
